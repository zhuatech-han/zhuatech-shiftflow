# 排班与替班操作手册

## 建立团队

管理员在部门、角色、用户页面建立账号，员工使用 ASSIGNED、排班员及主管使用 DEPARTMENT；管理员使用 ALL。维护角色时不要给员工系统管理权限。替班人需要 cover.write，知悉及不可排班需要 roster.own，业务读取需要 roster.read；系统允许自定义角色，分配前核查所需权限组合。

排班员在岗位页面创建启用的岗位，在岗位资格页面为同部门员工设置有效日期。一个员工和岗位只保留一条资格记录；调整日期须保留未来及进行中班次所需资格。人员资格是内部计划资料。

## 编排

建立班次，选择同部门岗位及员工、类型、上海时间、说明。草稿不占用员工时间，发布时才检查资格与冲突。重叠及间隔不足都会阻止发布。已发布不能编辑名称、时间或岗位；开始前取消或改派都须填写原因。改派保留时间及原发布的间隔规则。未发布草稿可以删除，发布历史必须保留。

## 员工协作

工作台查看本人未结束安排，进入详情“确认知悉”。需要替班时进入本人班次，“申请替班”选择同部门、启用、有资格、有 cover.write 且没有冲突的同事，填写说明。

指定同事在工作台接受或拒绝。接受不改变原安排。独立主管在替班待办批准或拒绝；主管本人若为任一当事人，不能批准自己的交接。批准时重新校验当前状态、指派版本、资格和冲突。批准后当前员工变更并重新等待知悉，原员工可通过获批历史查看原班次。

开始前可以处理交接；超过开始时间不能接受、批准、改派或取消。知悉截止为计划结束时刻。已结束仅说明计划时间经过，没有实际出勤结论。

## 不可排班与资料保护

员工在不可排班页面登记自己的时段，不能覆盖已发布班次；开始前可有说明地撤销，资料仍保留。员工不能查看同事的不可排班正文；排班员可见本部门，管理员可见全部。

员工或角色、岗位、资格修改若影响未结束的发布计划会被拒绝，变更将回滚。先取消或改派未来班次，进行中的班次须结束后再改变资格。新间隔参数只影响后续发布。

## 查询与导出

班次列表支持名称搜索、状态、本人当前指派、排序和每页20条。替班按状态筛选及分页；岗位/资格和管理目录在授权范围内搜索及分页。班次详情可下载 JSON，包含业务事件快照，无账号凭证及联系广告。统计显示未结束班次的完整计划分钟数，不能作为实际出勤或薪资来源。
